# STAGING / LECTURER DEMO Environment Matrix

This matrix is for a non-production deployment. Put values in Vercel/Render or the
authorized provider dashboards; never copy actual secrets from local `.env` into Git.

`staging.equa.io.vn` and `api-staging.equa.io.vn` are the currently referenced public
Web/API domains. DNS resolves to Vercel and Render respectively, but current API health
has not been verified. Confirm or replace these domains after Render/Vercel authorization.

## Database ownership

Use one managed PostgreSQL server only if it can host the five distinct logical databases
listed above. Create missing database names additively; do not drop or reset any existing
database. Each service receives a URL whose final database name matches its owner. The
Blueprint must not point multiple services at one shared application database.

## Staging provider limits

- Mailpit is local-only. Notification delivery is explicitly disabled for staging until a
  supported external provider is implemented/configured; Social-owned in-app invitations
  remain available.
- Identity registration requires the Resend provider and a verified sender domain. Do not
  substitute localhost Mailpit or an unverified personal address.
- Render free services are not suitable for this private, always-on multi-service topology;
  see the deployment checkpoint for plan/cost details.
- The private Key Value URL is passed to Kong as one Render-managed reference. The startup
  script accepts only `redis://` internal URLs and derives the hostname and port; it does
  not expose the datastore externally.
- `staging/demo` is excluded from the legacy Identity image/deploy-hook workflow. Its new CI
  and CodeQL checks run on branch pushes; Render Blueprint autodeploy is the intended path.
